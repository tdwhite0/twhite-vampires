# Procedural Audio System + Background Music

## Context
The game currently has no audio at all. We need to add procedurally generated chordal tones (slot-machine style, pentatonic scale so everything harmonizes) for game events, plus a procedural background music loop.

## Musical Design
- **Scale**: C Major Pentatonic (C, D, E, G, A) - all notes harmonize naturally
- **SFX**: Short sine-wave tones with attack/decay envelopes, random note selection for frequent events
- **Background music**: Procedural looping ambient pad using sustained pentatonic tones

| Event | Tone | Duration | Volume |
|-------|------|----------|--------|
| Enemy death | Random pentatonic note (C4-A4) | 80ms | 0.15 |
| XP gem collected | Random high note (C5/E5/G5) + harmonic shimmer | 60ms | 0.12 |
| Player damage | Low C3+E3 crunch with noise | 150ms | 0.35 |
| Level up | Rising arpeggio C4->E4->G4->C5 | 600ms | 0.30 |
| Game start | Bright chord C4+E4+G4 arpeggio | 500ms | 0.25 |
| Game over | Descending C4->G3->E3->C3 | 800ms | 0.30 |
| Weapon pickup | Two-tone chime C5->E5 | 200ms | 0.25 |
| Upgrade selected | Chord stab C5+G5 | 120ms | 0.20 |
| Projectile burst fire | Sharp E5 ping | 100ms | 0.10 |
| Lightning zap fire | A4 + crackle | 100ms | 0.10 |
| Flame aura pulse | Low G3 whoosh | 100ms | 0.07 |
| Boomerang fire | D4 spin tone | 100ms | 0.10 |
| Background music | Slow pentatonic pad loop | ~10s loop | 0.08 |

## Implementation

### Step 1: Create `src/systems/audio.rs` (new file, ~250 lines)
Core audio generation and resource setup:
- `generate_wav(sample_rate, samples) -> Vec<u8>` - encode i16 PCM samples as WAV bytes
- `generate_tone(freq, duration, sample_rate, attack_ms, decay_ms) -> Vec<i16>` - sine wave with envelope
- `generate_tone_with_harmonic(freq, duration, sample_rate, attack, decay, harmonic_ratio, harmonic_amp)` - for shimmery XP sounds
- `generate_arpeggio(notes_with_offsets, total_duration, sample_rate, attack, decay)` - for level up/game start/game over

# Plan: Game Font Setting

## Context
All text in the game uses Bevy's default font (`TextFont { ..default() }`). We want a "Game Font" setting in the A/V tab that lets players cycle through bundled font files, dynamically updating ALL text in the game.

## Approach

### 1. Add font files to `assets/fonts/`
Download 3 OFL-licensed `.ttf` fonts and place them in `assets/fonts/`:
- `PressStart2P-Regular.ttf` (pixel font)
- `VT323-Regular.ttf` (retro terminal font)
- `SpaceMono-Regular.ttf` (clean monospace)

These are all Google Fonts with OFL licenses.

### 2. Add `GameFontState` resource (`src/resources.rs`)
```rust
pub struct GameFont {
    pub name: &'static str,
    pub handle: Handle<Font>,
}

#[derive(Resource)]
pub struct GameFontState {
    pub fonts: Vec<GameFont>,
    pub selected: usize,
}
```
- `current()` method returns `self.fonts[self.selected].handle.clone()`
- `current_name()` returns the display name
- `cycle()` advances selected index (wraps around)
- First entry is "Default" with `Handle::default()` (Bevy's built-in font)

### 3. Load fonts in `setup_assets()` (`src/systems/startup.rs`)
After existing asset loading, use `asset_server.load("fonts/PressStart2P-Regular.ttf")` etc. and insert `GameFontState` resource.

### 4. Add `apply_font_to_all_text` system (`src/systems/ui/settings.rs`)
A system that runs whenever `GameFontState` changes:
```rust
fn apply_font_to_all_text(
    font_state: Res<GameFontState>,
    mut query: Query<&mut TextFont>,
) {
    if !font_state.is_changed() { return; }
    let font = font_state.current();
    for mut text_font in query.iter_mut() {
        text_font.font = font.clone();
    }
}
```
This is the key insight: instead of modifying every spawn site, we use a single reactive system that updates ALL existing `TextFont` components when the font changes. New text spawned with `..default()` will get updated on the next frame.

### 5. Add font cycle button to A/V settings tab (`src/systems/ui/settings.rs`)

### 6. Add `SettingsFontCycleButton` component (`src/components.rs`)
New marker component + add `FontCycle` variant to `SettingsButtonKind` enum.

### 7. Add `handle_settings_font_cycle` system (`src/systems/ui/settings.rs`)
On click: call `font_state.cycle()`, rebuild the settings panel. The `apply_font_to_all_text` system will pick up the change automatically.

### 8. Register new system in `main.rs`
- Add `apply_font_to_all_text` to the always-running Update systems
- Add `handle_settings_font_cycle` to the settings menu systems group

# Plan: Add 3 New Bosses with Unique Combat Mechanics

## Context

## Boss Designs

- **Attack - Fireball Barrage**: Phase-based (Idle -> Windup 1s -> Firing 2s -> Cooldown 3s). Fires 5 fireballs at 0.4s intervals aimed at player. Each fireball travels in a straight line and on expiry creates a lingering fire zone (radius 40, 8 dmg/tick, 3s). Reuses `ProjectileMaterial` (orange) for fireballs, `FlameAuraMaterial` for fire zones.

### 2. Necromancer
- **Sprite**: creatures.png index ~34, scale 4.5x
- **Stats**: HP 450, Speed 35, Contact Damage 15, Radius 40
- **Attack - Dark Magic**: Cycles through 3 attack types via `attack_index`:
  - **Summon**: Spawns 4-6 skeleton minions (normal enemies with `NecroSummon` tag, despawn when boss dies)
  - **Orb Attack**: Fires 3 slow homing dark orbs (speed 120, turn rate 1.5 rad/s, damage 20, lifetime 4s). Reuses `ProjectileMaterial` (purple).
  - **Teleport**: Blinks to random position 200-350 units from player with particle effects

### 3. Slime King
- **Sprite**: creatures.png index ~0, scale 5.0x, green tint
- **Stats**: HP 700, Speed 30, Contact Damage 35, Radius 55
- **Attack - Jump Slam**: Phase-based (Idle -> Windup 0.8s -> Jump 0.6s -> Land 0.3s -> Cooldown 2s). Squishes during windup, leaps to player's position, creates expanding shockwave ring on landing (damage 25, expands to radius 150). Visual: circle mesh at increasing scale.
- **Split on Death**: Spawns 2 mini-slimes (`SlimeSplit` entities, HP 100, speed 60, scale 2.5x) that chase player. Mini-slimes are NOT `Boss` entities - they get their own damage/death systems.

## Architecture Decisions

1. **Boss type identification**: Add `BossKind` enum, change `Boss` from unit struct to `Boss { kind: BossKind }`. 2. **Attack systems**: Each boss gets its own attack component + dedicated systems (matching the existing `BossLaser` + `boss_laser_attack` pattern). No generic phase machine.

3. **Sprite animation**: New bosses use a gentle scale-pulse animation (no atlas frames) since creatures.png has single frames per creature. Eyeball keeps its existing atlas animation.

4. **HP phase visuals**: New bosses use `Sprite.color` tinting at 66%/33% HP thresholds (eyeball keeps its texture swap).

5. **Boss rotation**: `BossSpawnTimer` gets `spawn_counter: u32`. Each spawn cycles: Eyeball -> Dragon -> Necro -> Slime -> repeat.
